# ng_ScopeTools 통합·독립 운영 계획

작성일: 2026-10-08  
상태: 새 프로젝트 세션에 전달할 제품·기술 계획. 이 문서 작성은 구현·배포를 포함하지 않는다.

## 1. 한 문장 목표

ScopeSentry의 자산 탐색·스캔, ng_pentest_server의 Project 기반 OSINT·Asset·Web·OOB 수집, ARTEX-ko의 AI 분석·검증을 **하나의 웹 제품 ng_ScopeTools**에서 연결한다. 초기에는 개인 PC에서 1명이 사용하고, 이후 팀이 접속하는 서버로 확장할 수 있게 설계한다. 통합 서버와 장기적인 제품 중심 언어는 Go다.

사용자가 원한 것은 기존 세 앱의 기능을 무작정 복제한 화면이 아니라, 한 Project와 Scope 안에서 발견 → 검토 → 수집/스캔 → 검증 → 근거 확인으로 이어지는 일관된 작업 흐름이다.

## 4. 목표 아키텍처

~~~text
사용자 브라우저: ng_ScopeTools 단일 UI
                    │
                    ▼
Go 통합 서버: 로그인·Project/Scope·권한·작업 요청·상태·결과 통합
     ├─ ng 수집 어댑터 → 기존 Python 서비스 → OSINT/Asset/Web/OOB
     ├─ ScopeSentry 어댑터 → 서버/MCP → Go 스캔 노드·플러그인
     └─ ARTEX 어댑터 → AI 작업·승인·근거·결과
                    │
                    ▼
공통 참조: Project / Scope / Asset / Run / Finding / Evidence / Provenance
~~~

1. 첫 버전에서는 서비스 간 **API/MCP 어댑터**로 연결한다. 다른 앱의 DB 테이블을 직접 읽고 쓰는 방식은 채택하지 않는다. 기존 SQLite, MongoDB/Redis, PostgreSQL 데이터는 각 서비스의 정본으로 둔다.
2. 통합 서버에 안정적인 Project·Scope·Asset·Run 식별자와 원본 서비스 ID의 매핑을 둔다. 기존 ng Project/Scope의 의미를 유지하고, 초기에는 기존 ID를 매핑한다. 정본 전환이 필요할 때는 migration·rollback·중복 처리 규칙을 먼저 정의한다.
3. 자산은 값만 합치지 않는다. 자산 종류, 정규화한 값, 원본 ID, 수집 시각, 출처, Project/Scope, 검증 상태를 함께 보존한다. 같은 도메인이 여러 IP로 해석되거나 여러 서비스에서 관찰된 경우에는 관계로 표시한다.
4. 사용자 흐름: 공개 자료에서 후보 발견 → 사용자가 Project/Scope에 등록 확인 → 스캔 또는 제한형 수집의 정확한 대상·요청 계획 확인 → 실행 → 근거 검토 → ARTEX 작업에 승인된 자산 전달 → 발견·검증 결과를 원 출처와 연결.
5. 실제 요청을 일으키는 실행은 작업별 대상·허용 범위·중단 조건·실행 기록을 보여준다. ARTEX의 승인창만을 전체 범위 통제 장치로 간주하지 않으며, 스캔 노드/AI 실행 환경에서도 범위를 제한한다.
6. 처음에는 로컬 단일 사용자 로그인으로 시작한다. 내부 레코드는 사용자/Project 소유와 권한 분리를 고려해 설계하고, 팀 서버 전환 시 인증·역할·감사 기록을 추가한다. 개인 AI 구독 로그인과 팀 공용 서비스 자격증명은 구분한다.

**전환 전략:** UI는 새 공통 셸과 Project 탐색을 먼저 만든다. 필요한 화면은 기존 서비스 경로로 연결해 기능을 유지하면서 고빈도 작업 화면부터 새 UI로 옮긴다. 최종 사용자 경험은 한 계정·한 탐색 체계·한 상태 언어로 수렴한다. 백엔드는 Go 통합 서버와 분리된 실행 노드로 구성할 수 있다. Python 기능을 옮길 때는 기존 DB 사본과 동일 입력·결과 비교를 통과한 기능부터 전환한다.

## 5. AI 실행 및 비용 경로

ARTEX-ko의 현재 모델 설정은 API 키를 요구한다. Go 에이전트 루프가 모델 Provider, 도구 호출, 재시도, 기록, 승인과 연결되어 있으므로 Claude Code/Codex를 설정 화면의 새 URL만으로 끼울 수는 없다.

| 모드 | 가능성과 설계 방향 |
| --- | --- |
| API 키 | ARTEX의 현행 기준선. 팀 서버 운영을 위한 기본 지원 경로로 남긴다. 실행 전에 계정·모델·비용 주체를 표시한다. |
| ChatGPT/Codex 플랜 | OpenAI의 공식 Sign in with ChatGPT OAuth로 승인받은 플랜 사용을 검토한다. 로컬 개인 프로젝트의 제공 조건과 계정 자격을 실제 등록·단일 추론 성공으로 확인한다. ARTEX의 자체 루프를 유지하려면 Responses 호환 어댑터를 구현하고, Codex 자체 에이전트를 쓰려면 app-server를 별도 실행 모드로 붙인다. 기존 Codex 앱의 토큰·쿠키를 추출해 재사용하지 않는다. |
| Claude Code 플랜 | 개인 로컬 작업에는 공식 Agent SDK 또는 claude -p 실행을 시험할 수 있다. 이것은 Claude Code 작업 위임 모드이며 ARTEX의 기존 모델 Provider와 같은 계약은 아니다. Anthropic의 제삼자 도구 인증·청구 안내가 별도로 있어, 팀/배포판의 기본 비용 경로로 확정하지 않는다. |

각 모드는 화면에서 **실행 주체, 플랜 한도 또는 API 과금 가능성, 계정, 작업 중단·실패 이유**를 분명히 보여준다. 한 모드가 실패해도 사용자 확인 없이 과금되는 다른 모드로 자동 전환하지 않는다. 자격증명은 브라우저에 노출하지 않고 서비스별로 분리해 저장한다.

## 6. 독립 운영·플러그인·업데이트

- 서버, UI, 스캔 노드, ARTEX 실행부, 사용 도구의 소스와 빌드 과정을 모두 목록화한다. ScopeSentry 서버 저장소만으로 스캐너·플러그인의 독립 운영이 완성됐다고 보지 않는다.
- 외부 플러그인 마켓 의존성을 없애기 위해 **자체 플러그인 소스 저장소/패키지 목록**, 버전 고정, 체크섬, 서명 또는 출처 검증, 설치 전 권한·인수 검토, 롤백 절차를 마련한다. 사용자 작성 Go 플러그인 템플릿과 테스트·배포 계약을 문서화한다.
- 스캔 템플릿은 “어떤 단계에서 어떤 플러그인을 실행하는지”를 명확히 표시한다. 노드 설치 상태와 템플릿 활성 상태를 구분하고, 의존성·매개변수·실행 전 예상 요청을 보여준다.
- subfinder/rad는 설정의 목적, 기본값, 변경 효과와 자격증명 필요 여부를 설명한다. 대형 YAML 편집기만 노출하지 않고 자주 쓰는 항목과 고급 원문 편집을 나눈다.
- ksubdomain 등의 실패는 설치 실패·실행 파일/권한·네트워크/DNS·타임아웃·파라미터를 구분해 로그와 UI에 표시한다. 스캔 완료 후 노드에 설치한 플러그인을 삭제하는 운영을 전제로 하지 않는다.
- 지문 업데이트는 원본, 버전, diff, 자체 수정 규칙과의 충돌, 백업·복원, 검증 데이터셋을 확인한 뒤 적용한다. 외부 업데이트가 한국어 UI나 로컬 규칙을 덮어쓰지 않게 한다.
- 별도 보유한 CVE PoC Python 코드(C:\Users\SECREZEN\CVE\backup\cves\...)는 형식·입출력·안전 경계부터 조사한다. 임의 Python 파일을 곧바로 서버에 올려 자동 실행하는 기능으로 간주하지 않는다. 선택한 PoC만 격리 실행 또는 Go 플러그인으로 이전할지 결정한다.

- 사용자 화면·사용법·오류·기본 설정·플러그인 설명의 중국어를 전수 조사해 자연스러운 한국어로 바꾼다. 새 제품 이름은 ng_ScopeTools를 사용한다. 로고는 결정 전 임시 글자 로고를 사용한다.
- 원본 상표·아이콘·링크·도메인·자동 업데이트 주소·Docker 이미지·문서·예제·의존성을 분리해 자체 빌드와 배포가 가능한지 확인한다. 제삼자 저작권 표시와 라이선스 고지는 정리해서 보존한다.
- **탐지 결과 보존이 우선이다.** 지문이나 정규식에서 중국어가 실제 응답과 비교되는 리터럴이면 단순 번역·삭제 시 탐지 결과가 달라진다. 사용자에게 보이는 이름·설명은 번역하되, 매칭 데이터는 회귀 테스트로 동등성이 입증될 때만 치환한다. “제품 어디에도 중국어 바이트가 없음”과 “중국어 응답에 대한 탐지 결과 완전 동일”이 충돌하는 규칙은 예외로 명시해 판단한다.
- 유출 계정 정보는 현재 ScopeSentry가 어떤 출처와 필드를 보유하는지 조사한 뒤 화면 추가 여부를 정한다. 없는 데이터를 관계도에 임의로 그리지 않는다.

## 8. UI/사용법 요구사항 — 기존 대화에서 반복된 문제

이 항목은 모두 **새 제품의 설계·회귀 검증 목록**이다. 현재 세 저장소에서 이미 고쳐졌다고 가정하지 않는다.

### 공통 화면

- 입력·버튼·검색 행·테이블 행·모달의 높이와 간격을 통일한다. “템플릿 이름” 같은 라벨은 작은 너비에서 글자 단위로 줄바꿈하지 않게 한다.
- 라이트·다크 양쪽에서 사이드바·드롭다운·표·차트 글자 대비를 확인한다. 사이드바의 펼침/선택 상태가 페이지마다 달라지거나 흰 배경에 회색 글자가 묻히지 않게 한다.
- 최신 사용자 제공 palette 토큰으로 색의 역할을 고정한다. 액션·상태·심각도·카테고리를 같은 색으로 혼용하지 않는다. 라이트 모드의 강한 파란색은 실제 화면에서 대비·채도를 다시 조정한다.
- 불필요한 카드·테두리·장식을 추가하지 않는다. 여백을 크게 늘려 정보량을 감추지 않고, 넓은 모니터 공간을 반응형으로 사용한다.
- “새로 만들기/삭제/가져오기” 툴바는 사용자가 지정한 **검색 아래·테이블 위의 왼쪽 위치**를 유지한다. 겹침은 크기·간격으로 해결하며 오른쪽으로 이동하지 않는다.
- 사용법은 각 메뉴의 입력, 실제 동작, 결과, 실패 시 조치, 외부 요청/비용 여부를 구체적으로 설명한다. 내부 용어만 나열하는 안내는 쓰지 않는다.

### 자산·작업·설정

- 자산 관계도는 동일 도메인·호스트·IP가 중복 객체처럼 보이는 원인을 데이터 ID와 표현 규칙으로 구분한다. 기본 top-down과 자유 배치를 선택할 수 있게 하되, 읽기 쉬운 층·선·항상 보이는 라벨·필터·자산 상세로 연결한다. 기능과 가독성을 위해 Maltego의 관계 탐색 방식을 참고할 수 있으나 UI를 그대로 복제하지 않는다.
- 스캔 템플릿 편집은 단계·사용 가능한 플러그인·선택 상태·실행 순서·옵션·예상 결과를 설명한다. 선택된 수와 목록이 일치해야 한다. 필터/모듈 전환 후 플러그인이 빈 화면으로 표시되는 문제를 재현·해결한다.
- 스캔 작업 → 프로젝트 동기화는 같은 이름의 프로젝트도 ID·상위 경로로 구분하고, 대상 선택·확인·성공·실패를 검증한다. 결과가 0인 경우와 요청 실패를 구분한다.
- 노드 플러그인 목록은 열 때마다 번호/순서가 바뀌지 않게 안정적인 정렬 키를 사용한다. 노드의 CPU·메모리는 어떤 자원과 측정 시점을 뜻하는지 적는다.
- POC 관리의 검색/툴바 수직 정렬과 새로 만들기 모달의 여백·편집기 크기를 고친다. PoC 내용에 요구하는 형식·언어·입출력·검증 방법을 바로 안내한다.
- 민감정보 규칙, 사전 관리, 포트의 생성 툴바 겹침을 수정한다. 시스템 Module Config의 각 값·권장 시작점·영향·중복 제거 설정을 설명한다. subfinder/rad 편집기는 적정 높이로 만든다.
- 상태 색상만으로 의미를 전달하지 않고 텍스트·아이콘을 병행한다. 표·그래프·팝오버·코드 편집기까지 키보드와 다크 모드에서 확인한다.

### 검증 화면 크기

기본 PC에서 HD/FHD/QHD/4K의 라이트·다크 화면을 확인한다. 특히 사이드바 확장, 넓은 설정 화면, 긴 테이블, 팝업, 그래프, 스캔 템플릿 필터, 작은 브라우저 너비를 검사한다. 실제 사용자 흐름에서 기능도 함께 검증한다.

## 9. 단계별 실행 계획과 완료 기준

### 0단계 — 권리·재현·기준선

1. 사용자가 확보한 ScopeSentry/ARTEX 별도 허가의 실제 범위를 기록한다. 원본 문서에는 ScopeSentry의 별도 상업 조건과 ARTEX의 온라인 테스트 제한 문구가 있으므로, 허가가 이를 어떻게 다루는지 확인한다. 공개·팀 배포 전 사용 자산의 라이선스 목록을 만든다.
2. 세 앱과 스캔 노드의 커밋·이미지 digest·빌드 방법·데이터 위치·환경 변수를 기록한다. DB·키·고객 자료는 저장소에 복사하지 않는다.
3. 현재 동작을 로컬 샘플 데이터로 재현하고, 사용자 스크린샷의 UI/기능 문제를 재현 가능한 테스트 목록으로 바꾼다.
4. 현재 ScopeSentry MCP와 ARTEX 동기화의 실제 호환성·실패 경로를 검증한다.

완료 기준: 소스·라이선스·데이터·연동 계약 목록, 안전한 로컬 기동, 재현 가능한 기준선.

### 1단계 — 단일 작업 문맥과 읽기 흐름

1. Go 통합 서버에서 Project/Scope와 서비스 ID 매핑을 제공한다. 기존 ng Project 자료는 그대로 둔다.
2. 세 서비스의 자산·작업·발견·근거를 출처별로 읽어 하나의 Project 화면에 표시한다. 원본으로 이동할 수 있다.
3. 첫 공통 UI 셸, 내비게이션, 팔레트 토큰, 라이트·다크, 오류/빈 상태를 만든다.

완료 기준: 사용자는 한 로그인·Project 선택으로 세 앱의 관련 자료를 볼 수 있고 원 출처를 추적할 수 있다.

### 2단계 — 실행과 결과 handoff

1. OSINT 후보 등록, ScopeSentry 스캔, ARTEX 작업으로 이어지는 정확 대상·범위·요청 계획 Preview/Confirm을 연결한다.
2. 실행 ID, 상태, 취소, 오류, 재시도와 도구 로그를 공통 화면에 표시한다. 동기화는 재시도해도 중복 결과를 무한 생성하지 않게 한다.
3. 실제 허가된 환경과 격리 테스트 환경을 구분한다.

완료 기준: 선택한 자산 1개를 Project 안에서 발견→스캔→결과 검토→AI 작업으로 전달하고 근거를 역추적할 수 있다.

### 3단계 — Go로 기능 이전과 독립 업데이트

1. 복잡도·사용 빈도·외부 의존성을 기준으로 Python 기능을 하나씩 Go로 이전한다. 각 기능은 기존 입력/결과·저장 데이터 비교와 rollback이 있어야 전환한다.
2. 스캔 노드/플러그인/지문 업데이트를 자체 소스와 버전으로 운영한다. 외부 마켓 연결은 선택 기능으로 격하한다.
3. 브랜딩·현지화·UI 통일을 완료하고 탐지 규칙 회귀 결과를 확인한다.

완료 기준: 한 제품의 자체 빌드·백업·복원·업데이트가 가능하며, 사용자가 지정한 핵심 UI 회귀 항목을 통과한다.

### 4단계 — 선택형 AI 연결과 팀 운영 준비

1. API 키 모드를 기준선으로 유지하면서 Codex/ChatGPT 플랜 모드의 공식 OAuth와 Claude Code 로컬 위임 모드를 각각 독립 실험한다.
2. 팀 운영 전 Project별 권한, 사용자별 AI 계정, 감사 로그, 서버 배포, 비밀 관리와 사용량 표시를 추가한다.

완료 기준: 모드별 과금/플랜 주체가 명확하고, 자격·한도·실패·중단을 사용자에게 설명할 수 있다. 팀 운영은 권한/격리 검증 뒤 별도 전환한다.

## 10. 새 프로젝트 세션의 첫 작업 지시

1. 이 문서와 위 세 저장소의 AGENTS/PROGRESS/README/설계 문서를 먼저 읽는다. 이 문서는 사용자와 합의한 방향이며, 각 저장소의 현재 지침·운영 데이터 보호 규칙도 확인한다.
2. 구현 전에 0단계의 증거를 수집해 실제 현재 버전과 이 문서의 가정이 다른 곳을 표시한다. 이미 수정된 UI나 기능을 재작업하지 않는다.
3. 첫 PR/작업 범위는 공통 Project/Scope ID 매핑과 ScopeSentry↔ARTEX 동기화 검증을 중심으로 작게 잡는다. 운영 DB를 직접 변환하거나 세 저장소를 한 번에 합치지 않는다.
4. 변경마다 입력·출력·출처·실행 부작용·롤백과 화면에서의 사용자 이해 가능성을 함께 확인한다.
5. 이 문서의 결정, 제안, 미검증 사실을 혼동하지 않는다. 새로운 제품 결정이 필요하면 사용자에게 선택지를 보여주고 구현 전에 확정한다.

## 11. 남아 있는 결정

- 로고/아이콘과 최종 브랜드 세부 스타일. 이름 ng_ScopeTools만 확정됐다.
- Go로 옮길 첫 Python 기능의 우선순위. 0~2단계 사용 흐름과 실제 운영 비용을 측정한 뒤 정한다.
- 새 통합 UI의 최종 프런트엔드 기술과 저장소 구조. 먼저 Project·자산·스캔 템플릿·ARTEX 작업 화면의 짧은 프로토타입을 비교한다.
- API/MCP 연결에 필요한 제품별 최소 권한, 사용자별 계정 정책, 결과 충돌 시 정본 규칙.
- 리터럴 중국어가 탐지 패턴인 경우 “모든 중국어 바이트 제거”와 “탐지 결과 동일” 중 어떤 기준을 우선할지. 기본 계획은 탐지 결과 보존과 사용자 노출 텍스트의 한국어화다.
